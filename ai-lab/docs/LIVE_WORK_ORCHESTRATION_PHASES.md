# Live work orchestration — phased delivery

This document breaks migration of the ChatGPT **Daily Work Planner** into **ai-lab** into safe, reviewable phases. See `[LIVE_WORK_ORCHESTRATION_SPEC.md](LIVE_WORK_ORCHESTRATION_SPEC.md)` for the full behavior design.


| Phase                                                  | Scope                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **9 — Foundation**                                     | Data model (`brain/live_work_orchestration/schema.py`), read-only worker stubs, snapshot builders under `state/live_work_orchestration/`, read-only `compile_daily_plan_preview`, snapshot script, GET `/api/live-work/status` and `/api/live-work/plan-preview`, tests. **No** live desktop monitoring, **no** auto ClickUp/calendar writes, **no** autonomous replanning.                                                                                                                                                                                                                                     |
| **10 — ClickUp action loop**                           | Deterministic ClickUp list routing, local **proposal** queues (`clickup_action_queue.json`, `clickup_clarification_queue.json`), one-question clarification discipline, `generate_clickup_action_recommendations`, read-only `GET /api/live-work/clickup-queue` and `GET /api/live-work/clickup-preview`. **No** automatic task creation, comments, or status updates—approval enforcement unchanged. See `[LIVE_WORK_CLICKUP_ACTION_LOOP.md](LIVE_WORK_CLICKUP_ACTION_LOOP.md)`.                                                                                                                               |
| **11 — Local repo activity ingestion**                 | Read-only local git metadata ingestion lane, progress signals, and integration into `daily_progress_snapshot`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                  |
| **12 — GitHub PR / issue ingestion**                   | Read-only GitHub PR/issue ingestion lane and correlation to local repo activity for feature states (`in flight`, `blocked`, `review`, `ready_to_merge`, `merged`) plus planner-facing remote status signals. No GitHub writes/comments. See `[LIVE_WORK_GITHUB_ACTIVITY_INGESTION.md](LIVE_WORK_GITHUB_ACTIVITY_INGESTION.md)`.                                                                                                                                                                                                                                                                                 |
| **13 — Project timetable + estimation guardrails**     | Range-only feature effort estimation, confidence/risk/evidence enforcement, timetable build from Phase 11+12 signals, and clarification generation for unknown/low-confidence timeline inputs. No autonomous replanning. See `[LIVE_WORK_TIMETABLE_BUILDER.md](LIVE_WORK_TIMETABLE_BUILDER.md)`.                                                                                                                                                                                                                                                                                                                |
| **14 — Estimation calibration loop**                   | Record estimate snapshots and evidence-backed actuals, evaluate bias (under/over/accurate), build conservative calibration profiles, and feed optional range adjustments back into estimation while preserving guardrails and range-only output. See `[LIVE_WORK_ESTIMATION_CALIBRATION.md](LIVE_WORK_ESTIMATION_CALIBRATION.md)`.                                                                                                                                                                                                                                                                              |
| **15 — Calibration UX + measured-time fallback**       | Measured/inferred time evidence from repo + GitHub snapshots, `decide_calibration_source` hierarchy (**measured_actual → inferred_actual → user_confirmed_actual → unknown_needs_confirmation**), gated one-question clarification proposals (user clarification as **fallback** only), optional auto-record of high/medium confident actuals, timetable + compiler calibration health fields, script flags (`--derive-actuals`, `--ask-missing`, `--dry-run`). No new ingestion lanes; range-only estimates unchanged. See `[LIVE_WORK_MEASURED_TIME_CALIBRATION.md](LIVE_WORK_MEASURED_TIME_CALIBRATION.md)`. |
| **16 — Local work timestamp enrichment + git hygiene** | Repo activity rows gain bounded **file mtime** samples (status-listed paths only), **combined activity windows** (file + commit bounds), bounded **commit timestamps**, and read-only **git hygiene** hints (`commit_needed`, `push_needed`, ahead/behind, summaries). Strengthens Phase 15 `derive_measured_time_from_repo_activity` without reading file contents, full-repo scans, or mutating git state. See `[LIVE_WORK_REPO_ACTIVITY_INGESTION.md](LIVE_WORK_REPO_ACTIVITY_INGESTION.md)` and `[LIVE_WORK_MEASURED_TIME_CALIBRATION.md](LIVE_WORK_MEASURED_TIME_CALIBRATION.md)`.                         |
| **17 — Financial / bills ingestion (safe lane)**       | Manual-first **financial obligations** (bills): explicit amounts/dates/status only; **hard constraint** awareness for planning (overdue / due soon / risk). **No** payments, bank mutations, invented figures, budgeting/forecasting, or external bank APIs yet. ClickUp clarification **proposals** for missing/conflicting fields, routed to `Agent Bills`, `Company Finances`, or `Nugz Bills`. See `[LIVE_WORK_BILLS_INGESTION.md](LIVE_WORK_BILLS_INGESTION.md)`.                                                                                                                                          |


Cross-cutting: **approval enforcement** and **prepared-context quality gates** are never weakened; new actions extend existing patterns rather than bypassing them.
